## 项目概述
在博客中添加一个**虚拟 ACM 比赛代码协作页面**，所有注册用户属于同一支队伍。用户可以创建多场比赛，每场比赛有 A–K 共11道题。每个用户在自己的分支上提交代码，可查看队友分支，更新动态实时记录。无需队伍管理、队长或权限分级。

---

## 技术栈建议
- **前端**：HTML + CSS + JavaScript（可选用 Vue/React 以简化状态管理，但需与博客样式一致）
- **后端**：Node.js（Express）或 Python（Flask/FastAPI），提供 REST API
- **数据库**：SQLite 或 PostgreSQL（存储用户、比赛、提交、动态）
- **认证**：Session/Cookie 或 JWT
- **定时轮询**：前端 `setInterval` 每10-15秒请求更新列表

## 任务列表

### 1. 数据库设计
1. **用户表**：id, username（唯一）, password（哈希存储）, created_at  
2. **比赛表**：id, name, creator_id, created_at, is_finished（默认 false）  
3. **提交表**：id, user_id, contest_id, problem（char ‘A’-‘K’）, code（文本）, updated_at  
   - 每个用户在同一比赛同一题目只保留一条记录（唯一约束：user_id, contest_id, problem），更新时覆盖代码和更新时间。  
4. **动态表**：id, contest_id, user_id, problem, action（‘update’/‘delete’）, created_at  
   - 记录提交和删除操作。

---

### 2. 后端 API 开发
#### 2.1 用户系统
- POST `/api/register`：接收 username, password，密码加密后存储，返回成功/失败。  
- POST `/api/login`：验证用户名密码，创建会话或返回 token。  
- GET `/api/me`：返回当前登录用户信息。  
- POST `/api/logout`：销毁会话。

#### 2.2 比赛管理
- GET `/api/contests`：返回所有比赛列表（id, name, creator, created_at）。  
- POST `/api/contests`：创建新比赛（需登录），接收 name。  
- GET `/api/contests/:id`：返回比赛详情（名称、是否结束等）。

#### 2.3 题目与代码提交
- GET `/api/contests/:id/problems`：返回固定列表 A–K（前端也可硬编码）。  
- GET `/api/contests/:id/submissions?problem=X`：返回该比赛、该题目下**所有用户**的最新提交（用于分支列表）。实际数据结构：每个用户一条提交，包含 username, code, updated_at。  
- PUT `/api/contests/:id/submissions/:problem`：提交/更新当前用户在该题目的代码（需登录）。请求体包含 code。后端执行 upsert（存在则更新，否则插入），同时向动态表插入一条 `update` 记录。  
- DELETE `/api/contests/:id/submissions/:problem`：删除当前用户在该题目的提交（清空代码）。后端删除对应记录，并插入一条 `delete` 动态记录。

#### 2.4 更新动态
- GET `/api/contests/:id/activities?limit=20`：返回该比赛最近动态，包含 username, problem, action, created_at，按时间倒序。  
- 动态仅由提交和删除操作触发，不在 API 中手动创建。

#### 2.5 权限控制
- 所有用户自动拥有查看所有比赛和所有分支的权限，无需额外检查。  
- 修改/删除操作仅允许操作自己的提交（通过 session 用户 ID 校验）。

### 3. 前端页面开发（样式与博客 index 一致）
#### 3.1 公共部分
- 将博客的头部、导航、CSS 样式应用到所有新页面，保持视觉统一。  
- 添加定时轮询逻辑：在比赛主页和题目页，每 12 秒调用更新动态 API 刷新时间线。

#### 3.2 登录/注册页
- 登录表单（用户名、密码）和注册表单。  
- 登录成功后跳转到比赛大厅；未登录访问任何页面重定向到登录页。  
- 若博客已有用户系统，则复用；否则独立实现。

#### 3.3 比赛大厅页（`/lobby`）
- 登录后默认进入此页。  
- 显示已创建比赛列表（卡片或表格），每项显示比赛名、创建者、创建时间。  
- “创建新比赛”按钮：点击弹出输入框，填写比赛名，调用 API 创建，成功后刷新列表。  
- 点击比赛名进入该比赛的题目主页（路由如 `/contest/:id`）。

#### 3.4 比赛题目主页（`/contest/:id`）
- 顶部左侧显示比赛名，右侧“返回大厅”链接/按钮。  
- 题目卡片区域：A–K 共11个卡片，排列方式参照博客文章列表。每个卡片上显示题号（如 “Problem A”）和最新提交状态（例如“已提交/未提交”，可根据当前用户是否有该题提交判断）。  
- 点击卡片进入题目页（`/contest/:id/problem/:problem`）。  
- 更新动态时间线区域（下方或侧边栏）：
  - 实时显示动态，格式：“**张三** 更新了 **C题** · 2分钟前”，点击可跳转到对应队员的该题页面。  
  - 若动作为“删除”，显示“张三 删除了 C题 提交”。  
  - 点击跳转逻辑：构造 URL `/contest/:id/problem/:problem?user=张三`，自动切换分支。

#### 3.5 题目页（`/contest/:id/problem/:problem`）
- 左上角**分支选择器**（下拉菜单或列表），列出所有已在该比赛提交过代码的队员（或所有注册用户），默认选中当前登录用户自己。  
- 选择不同队员后，下方展示该队员该题的代码（纯文本，等宽字体，无高亮）。  
- 若选择的是自己：
  - 显示一个 `textarea` 代码编辑框，预填当前代码（可能为空）。  
  - 两个按钮：“提交”（保存并更新）和“删除”（清空代码）。  
  - 提交或删除后更新动态列表（通过轮询自然更新）并提示成功。  
- 若选择的是他人：仅展示代码（只读），无编辑框和按钮。  
- 若该队员未提交代码，显示“尚未提交”。  
- 页面需处理从动态链接跳转过来的情况：读取 query 参数 `?user=xxx`，自动将分支选择器设置为该用户，并加载对应代码。  
- 页面需包含“返回比赛主页”链接。

#### 3.6 前端状态与交互细节
- 提交代码后无需跳转，停留在当前页，但清空编辑框提示成功。  
- 删除时弹出确认框。  
- 定时轮询只更新当前比赛的动态时间线（比赛主页）或当前题目页的分支列表（有新提交时可能增加分支选项）。轮询时避免闪烁，仅更新变化数据。  
- 若比赛被标记为“结束”（未来扩展），则隐藏所有编辑/提交/删除按钮，仅保留查看。当前版本无需实现结束逻辑。
