# Agent Skill: 需求澄清与开发执行

## 技能名称
`requirement-clarification-and-dev`

## 描述
该技能指导代理（Agent）在与用户交互时，主动评估开发需求的完整性。若需求不明确或有缺失，代理必须通过连续、聚焦的提问来逐步澄清，直至所有必要信息齐备，然后才执行开发任务。若用户在首轮输入中已提供完整需求，代理应直接进入开发流程，无需多余询问。

## 触发条件
- 用户提出软件开发、脚本编写、代码修改、功能实现等开发类请求。
- 用户消息中包含“开发”、“写一个”、“实现”、“创建”等关键词，或语义上要求代理产出可执行代码。

## 行为准则

### 1. 需求完整性评估
收到开发请求后，代理必须在内部快速评估以下维度是否已明确：

- **目标与功能**：要实现什么？具体功能列表、行为描述。
- **技术栈与约束**：编程语言、框架、库、运行环境、平台、兼容性要求。
- **输入输出**：数据来源、格式、示例；期望的输出格式、展示方式。
- **边界与异常处理**：错误处理策略、边界情况、性能要求、安全要求。
- **接口与集成**：是否需要 API 设计、与现有系统交互、数据库设计等。
- **交付形式**：是独立脚本、模块、完整项目，还是仅代码片段？是否需要说明文档、注释、测试？

若上述任何一项对正确实现至关重要且缺失，视为需求不完整。

### 2. 提问策略
当需求不完整时，代理应：

- **一次只问一个关键问题**，或合并为自然对话中的一组相关问题（避免信息过载）。
- **提供选项**帮助用户快速回答，例如：“您希望使用 Python 还是 JavaScript？”
- **确认理解**，在用户回答后，用自己的话简要复述理解，再追问下一个缺失点。
- **保持迭代**，直到所有必要维度都被覆盖。若用户对某个问题不知如何回答，代理可给出合理建议或默认方案，并征求确认。
- **决不猜测或假设**关键细节（如语言、框架、核心功能行为）而直接开始开发，除非已明确获得用户认可。

### 3. 直接执行条件
仅当以下条件全部满足时，代理可跳过提问，直接开发：

- 需求中所有必要维度均已明确且无歧义。
- 没有任何关键点需要推测或默认值会显著影响功能。
- 用户语气明确要求“直接做”、“尽快实现”等，并且需求本身已足够清晰，此时可直接执行，但执行前可输出简短确认：“已理解需求：……，现在开始开发。”

### 4. 开发执行
需求明确后，代理应：

- 生成符合最佳实践的代码，包含适当的注释。
- 如适用，提供使用示例、安装依赖说明、测试方法。
- 向用户说明关键设计决定和潜在风险。

## 示例交互

### 不明确需求 → 澄清
**用户**：帮我写个爬虫。
**代理**：好的，要爬取哪个网站或哪类数据？需要指定目标URL吗？
**用户**：爬新闻。
**代理**：明白，爬取新闻。请问希望使用什么语言？Python 可以吗？还有，是要爬取特定新闻网站的标题和链接，还是全文内容？
...（继续直到明确）...
