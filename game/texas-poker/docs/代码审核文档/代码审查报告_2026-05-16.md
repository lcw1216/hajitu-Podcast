## 2. BUG 与功能性缺陷

### 🔴 BUG-01: 牌型引擎对比功能存在冗余计算，且牌型等级信息未有效传递

**问题位置**: [engine/hand_eval.cpp:L88-L221](file:///d:/gitproject/game/texas-poker/engine/hand_eval.cpp#L88-L221)

**问题描述**:
`eval_hand()` 函数内部会遍历全部 C(7,5)=21 种组合找出最优牌型，但**只返回等级数字**（0-9），丢弃了具体的踢脚牌（kicker）信息。当 Python 端需要比较两手牌（如摊牌阶段）时，`compare_hands()` 不得不**重新**遍历全部 21 种组合，导致两倍的计算开销。

在 [game.py:L216-L223](file:///d:/gitproject/game/texas-poker/server/game.py#L216-L223) 中，摊牌阶段先调用 `eval_hand()` 获取等级，再调用 `compare_hands()` 做精确比较，每个玩家做了两次完整的 C(7,5) 评估：

```python
rank = eval_hand(seven_cards)         # 一次完整评估
# ...
cmp = compare_hands(r["cards"], winners[0]["cards"])  # 再次完整评估
```

**严重程度**: 🔴 严重

**修改方案**:
在 C++ 端新增 `eval_hand_full()` 函数，返回完整的 `HandScore` 结构体（含等级和踢脚），Python 端直接使用该结果进行比较，避免重复计算。或者将 `compare_hands` 的调用逻辑改为先比较已知等级，等级相同时再调用 C++ 做精确比较。

### 🔴 BUG-02: C++ 牌型库硬编码 DLL 路径，跨平台兼容性缺失

**问题位置**: [server/hand_eval.py:L17-L18](file:///d:/gitproject/game/texas-poker/server/hand_eval.py#L17-L18)

**问题描述**:
Python 封装层硬编码了 Windows DLL 路径，未提供 Linux/macOS 的 `.so`/`.dylib` 回退逻辑。在非 Windows 平台上直接导入会导致 `OSError` 崩溃。

```python
_dll_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "hand_eval.dll")
_lib = ctypes.CDLL(_dll_path)  # 在 Linux/macOS 上直接报错
```

**严重程度**: 🔴 严重

**修改方案**:
根据平台自动选择文件扩展名：

```python
import sys
_ext = {"win32": ".dll", "darwin": ".dylib"}.get(sys.platform, ".so")
_dll_path = os.path.join(os.path.dirname(...), f"hand_eval{_ext}")
if not os.path.exists(_dll_path):
    raise ImportError(f"牌型引擎库未找到: {_dll_path}")
```

**问题位置**: [server/main.py:L35-L52](file:///d:/gitproject/game/texas-poker/server/main.py#L35-L52)

### 🔴 BUG-04: 加注金额计算存在歧义，可能产生预期外的全下行为

**问题位置**: [server/game.py:L130-L139](file:///d:/gitproject/game/texas-poker/server/game.py#L130-L139)

**问题描述**:
`process_action` 中 raise 的金额计算逻辑存在歧义：

```python
elif action == "raise":
    raise_amount = max(amount, self.current_bet + self.min_raise)
    if raise_amount > player.chips + player.current_bet:
        raise_amount = player.chips + player.current_bet
    self.last_raise_amount = raise_amount - self.current_bet
```

当玩家筹码不足以完成最小加注额时，`raise_amount` 会被截断为 `player.chips + player.current_bet`，即全下（all-in）。这是合理行为，但前端没有给玩家明确提示这是一个 all-in 操作。同时 `last_raise_amount` 的计算逻辑在 all-in 场景下为 `(player.chips + player.current_bet) - self.current_bet = player.chips`，这可能导致后续玩家的 `min_raise` 计算出现异常。

**严重程度**: 🔴 严重

**修改方案**:
1. 在 all-in 场景下设置 `last_raise_amount = 0`（all-in 不改变加注额度）
2. 向客户端发送的 game_state 中增加 `isAllIn` 标记
3. 前端在 raise 金额达到玩家全部筹码时显示"全下"

## 3. 性能问题

### 🟠 PERF-01: 牌型评估中 21 种组合被反复计算

**问题位置**: [engine/hand_eval.cpp:L178-L221](file:///d:/gitproject/game/texas-poker/engine/hand_eval.cpp#L178-L221)

**问题描述**:
`eval_hand()` 和 `compare_hands()` 各自独立遍历 C(7,5)=21 种组合。在摊牌阶段，N 个玩家的场景下，`eval_hand()` 调用 N 次 + `compare_hands()` 调用 N-1 次 = 约 2N 次完整评估。当 8 人满桌时，总共需要评估约 8×21 + 7×21 = 315 次 C(5) 组合。

**严重程度**: 🟠 主要

**修改方案**:
将评估结果缓存。在 C++ 中新增函数一次评估两手牌：

```cpp
// 新增接口：同时评估两手牌并比较
int compare_hands_evaluated(int best_rank_a, const int hand_a[7], int best_rank_b, const int hand_b[7]);
```

在 Python 端，先比较等级，不同则直接返回，相同才调用 C++ 做踢脚比较。

2. 或采用虚拟 DOM diff 策略，仅更新变化的行

### 🟠 PERF-03: SQLite 连接未复用，线程本地存储可能泄漏

**问题位置**: [server/app.py:L10-L18](file:///d:/gitproject/game/texas-poker/server/app.py#L10-L18)

**问题描述**:
`get_db()` 使用线程本地存储创建数据库连接，但**没有任何清理机制**。当线程结束时，对应的 SQLite 连接不会被关闭，可能导致资源泄漏。对于短连接测试场景影响较大。

```python
_db_local = {}

def get_db():
    import threading
    thread_id = threading.get_ident()
    if thread_id not in _db_local:
        conn = sqlite3.connect(config.DB_PATH, timeout=30)
        _db_local[thread_id] = conn
    return _db_local[thread_id]
```

**严重程度**: 🟠 主要

**修改方案**:
1. 使用 `threading.local()` 替代手动字典管理
2. 或者实现连接池，限制最大连接数并回收空闲连接
3. 注册 `threading._after_fork` 或使用 `weakref` 回调清理

## 6. 架构与设计问题

### 🟠 ARCH-01: HTTP 服务与 WebSocket 服务状态割裂

**问题位置**: 架构层面

**问题描述**:
HTTP 服务（app.py）和 WebSocket 服务（main.py）是**两个独立进程**，不共享游戏状态。HTTP 端的"房间管理"（创建/查询房间）存储在 SQLite 中，而 WebSocket 端的"游戏对局"（GameState）仅存在于进程内存中。这导致：

1. HTTP 接口无法获知游戏对局的实时状态（正在游戏中的玩家数等）
2. 无法从 HTTP 端触发游戏操作
3. 如果 WebSocket 服务重启，所有游戏状态丢失

**严重程度**: 🟠 主要

**修改方案**:
1. **短期**: 在 HTTP 端增加 `/api/rooms/:room_id/status` 接口，查询房间实时状态
2. **长期**: 将游戏状态迁移至 Redis 或共享内存，支持进程间状态共享
3. 或者合并为单一进程，使用 asyncio 同时处理 HTTP 和 WebSocket

---

### 🟠 ARCH-02: 游戏状态机中庄家位置计算方法存在歧义

**问题位置**: [server/game.py:L54-L59](file:///d:/gitproject/game/texas-poker/server/game.py#L54-L59)

**问题描述**:
`start_game()` 中庄家索引 `dealer_index` 的计算与玩家数量相关，但未考虑出局(out)玩家：

```python
self.dealer_index = (self.dealer_index + 1) % len(self.players)
```

当有玩家出局（`state == "out"`）时，`len(self.players)` 仍然包含出局玩家，可能导致庄家落在出局玩家位置上。

**严重程度**: 🟠 主要

**修改方案**:
```python
active_count = len([p for p in self.players if not p.is_out()])
self.dealer_index = (self.dealer_index + 1) % len(self.players)
while self.players[self.dealer_index].is_out():
    self.dealer_index = (self.dealer_index + 1) % len(self.players)
```

### 🟡 ARCH-04: WebSocket 无心跳检测机制

**问题位置**: [server/main.py](file:///d:/gitproject/game/texas-poker/server/main.py)

**问题描述**:
WebSocket 服务端未发送 ping 帧检测客户端存活状态。如果客户端非正常断开（如网络闪断、休眠），服务端无法及时发现并清理玩家连接，导致"幽灵玩家"占据房间位置。

**严重程度**: 🟡 次要

**修改方案**:
在 WebSocket handler 中添加心跳检测：

```python
async def heartbeat(websocket):
    while True:
        await asyncio.sleep(30)
        try:
            pong = await websocket.ping()
            await asyncio.wait_for(pong, timeout=10)
        except:
            await websocket.close()
            break
```

## 7. 测试覆盖问题

### 🟡 TEST-01: C++ hand_eval 核心逻辑无自动化测试

**问题位置**: [engine/test.cpp](file:///d:/gitproject/game/texas-poker/engine/test.cpp)

**问题描述**:
`test.cpp` 是手动测试工具，需要用户交互式输入。没有自动化的单元测试验证以下边界场景：
- A-2-3-4-5 最小顺子（wheel）的识别

### 9.6 修改过程中发现并修复的额外 Bug

#### 额外 Bug-01: `_next_phase` 未调用 `_showdown` — ✅ 已修复

**问题位置**: [server/game.py:L205-L210](file:///d:/gitproject/game/texas-poker/server/game.py#L205-L210)

**问题描述**: `_next_phase` 中当 phase 为 "river"（索引 4）时，条件 `phase_idx >= len(PHASES) - 1` 为 `4 >= 5`（False），导致 `_showdown()` 未被调用。代码继续执行设置 `next_phase = "showdown"`，但仅修改了 `self.phase` 而未执行摊牌逻辑，底池永远不会分配给赢家。

**修改方案**: 在 `_next_phase` 中添加 `if next_phase == "showdown"` 判断，直接调用 `_showdown()` 并返回。

**影响**: 这是一个严重的功能性 bug，导致所有正常打到摊牌阶段的牌局都无法正确结算。

---

#### 额外 Bug-02: `process_action` 未更新 `self.pot` — ✅ 已修复

**问题位置**: [server/game.py:L145-L165](file:///d:/gitproject/game/texas-poker/server/game.py#L145-L165)

**问题描述**: `process_action` 中 call 和 raise 操作扣减了玩家筹码但未将差额加入 `self.pot`，导致底池金额不守恒。盲注在 `_post_blinds` 中正确计入了 pot，但后续所有下注操作都未更新 pot。

**修改方案**: 在 call 和 raise 操作中，通过 `chips_before - player.chips` 计算实际扣减金额并加入 `self.pot`。

**影响**: 这是一个严重的功能性 bug，导致底池金额始终只有盲注之和，所有跟注和加注的筹码都"消失"了。

---

#### 额外 Bug-03: `_showdown` 未处理只剩一人的情况 — ✅ 已修复

**问题位置**: [server/game.py:L224-L260](file:///d:/gitproject/game/texas-poker/server/game.py#L224-L260)

**问题描述**: 当所有其他玩家弃牌只剩一人时，`_showdown` 仍尝试调用 `eval_hand_full` 评估牌型，但此时公共牌可能不足 5 张（如 preflop 阶段弃牌），导致 7 张牌数量不足抛出 `ValueError`。

**修改方案**: 在 `_showdown` 开头检查活跃玩家数量，若只剩 1 人则直接判定获胜，无需评估牌型。

**影响**: 导致所有"一人弃牌另一人直接获胜"的场景崩溃。
