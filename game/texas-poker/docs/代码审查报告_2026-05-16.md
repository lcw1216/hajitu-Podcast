### SEC-01: Token 存储于 localStorage，易受 XSS 攻击

**文件**: [login-in.html](file:///d:/gitproject/game/texas-poker/login-in.html#L157-L161)  
**严重级别**: 🔴 Critical  
**问题描述**: 用户认证 Token 存储在 `localStorage` 中，任何 XSS 漏洞都可以通过 `localStorage.getItem('token')` 窃取 Token，进而冒充用户身份。

```javascript
// 当前代码 — login-in.html 第157-161行
localStorage.setItem('user_id', data.user_id);
localStorage.setItem('username', data.username);
localStorage.setItem('token', data.token);
localStorage.setItem('chips', data.chips);
```

**修改方案**: 使用 HttpOnly + Secure + SameSite Cookie 存储 Token，前端无法通过 JavaScript 访问。

**步骤**:
1. 后端登录接口通过 `Set-Cookie` 响应头下发 Token
2. 前端移除所有 `localStorage.setItem('token', ...)` 调用
3. WebSocket 连接时从 Cookie 中读取 Token（需后端配合）

```python
# 后端修改 — app.py login 函数
resp = Response.json({
    "ok": True,
    "user_id": user["id"],
    "username": user["username"],
    "chips": user["chips"],
})
resp.set_cookie("token", token, max_age=86400, http_only=True, secure=True, same_site="strict")
resp.set_cookie("user_id", str(user["id"]), max_age=86400, http_only=True, secure=True, same_site="strict")
return resp
```

**预期效果**: Token 对 JavaScript 完全不可见，从根本上消除 XSS 窃取 Token 的风险。

### SEC-03: 登录/注册接口无速率限制

**文件**: [app.py](file:///d:/gitproject/game/texas-poker/server/app.py#L119-L145)  
**严重级别**: 🔴 Critical  
**问题描述**: `/api/login` 和 `/api/register` 接口没有任何速率限制，攻击者可以进行暴力破解密码或批量注册。

**修改方案**: 添加基于 IP 的速率限制中间件。

```python
# 新增文件 — rate_limit.py
import time
import threading
from collections import defaultdict

class RateLimiter:
    def __init__(self, max_requests=10, window_seconds=60):
        self.max_requests = max_requests
        self.window = window_seconds
        self._requests = defaultdict(list)
        self._lock = threading.Lock()

    def is_allowed(self, key):
        now = time.time()
        with self._lock:
            self._requests[key] = [t for t in self._requests[key] if now - t < self.window]
            if len(self._requests[key]) >= self.max_requests:
                return False
            self._requests[key].append(now)
            return True

login_limiter = RateLimiter(max_requests=5, window_seconds=60)
register_limiter = RateLimiter(max_requests=3, window_seconds=300)
```

```python
    if not login_limiter.is_allowed(client_ip):
        raise ForbiddenError("请求过于频繁，请稍后再试")
    # ... 原有逻辑
```

**预期效果**: 限制同一 IP 的登录尝试频率，有效防御暴力破解。

### BUG-01: 缺少边池（Side Pot）处理逻辑

**文件**: [game.py](file:///d:/gitproject/game/texas-poker/server/game.py#L237-L276)  
**严重级别**: 🟠 High  
**问题描述**: 当玩家 All-in 时，当前实现将全部底池平均分配给赢家，没有处理边池场景。例如：玩家A有100筹码，玩家B有500筹码，A全押后B继续加注，A只能赢得200（100×2）的底池，剩余部分应归B。

```python
# 当前代码 — game.py _showdown 函数
win_amount = self.pot // len(winners)
for w in winners:
    w["player"].chips += win_amount
```

**修改方案**: 实现边池计算逻辑。

```python
def _calculate_pots(self):
    active_players = [p for p in self.players if p.is_active() or p.state == "all_in"]
    if not active_players:
        return []

    bets = sorted(set(p.total_bet for p in active_players if p.total_bet > 0))
    pots = []
    prev_level = 0

    for level in bets:
        pot_amount = 0
        eligible = []
        for p in self.players:
            contribution = min(p.total_bet, level) - min(p.total_bet, prev_level)
            pot_amount += contribution
            if p.is_active() and p.total_bet >= level:
                eligible.append(p)
        if pot_amount > 0 and eligible:
            pots.append({"amount": pot_amount, "eligible": eligible})
        prev_level = level

    return pots
```

**预期效果**: All-in 场景下底池分配正确，避免筹码计算错误。

### BUG-05: _next_active_index 可能无限循环

```python
def _next_active_index(self, current_index):
    n = len(self.players)
    idx = (current_index + 1) % n
    attempts = 0
    while self.players[idx].is_out() and attempts < n:
```

**预期效果**: 防止无限循环，在无活跃玩家时给出明确错误。

### BUG-07: _is_betting_round_over 未正确处理 All-in 玩家

```python
def _is_betting_round_over(self):
    active_players = [p for p in self.players if p.is_active()]
    if len(active_players) <= 1:
        return True

    can_act_players = [p for p in active_players if p.chips > 0]

    if not can_act_players:
        return True

    all_matched = all(p.current_bet >= self.current_bet for p in can_act_players)
    all_acted = self._acted_count >= len(active_players)

    return all_matched and all_acted
```

**预期效果**: All-in 场景下下注轮正确结束。

### PERF-01: C++ 牌型评估使用暴力组合枚举

**文件**: [hand_eval.cpp](file:///d:/gitproject/game/texas-poker/engine/hand_eval.cpp#L133-L155)  
**严重级别**: 🟡 Medium  
**问题描述**: `eval_hand` 和 `eval_hand_full` 都使用 C(7,5)=21 次的暴力枚举，且 `compare_hands` 重复计算两次（42次枚举）。虽然21次不多，但 `eval_hand` 和 `eval_hand_full` 的循环体完全重复。

**修改方案**: 提取公共的枚举逻辑为辅助函数，减少代码重复。

```cpp
static HandScore find_best_hand(const int cards[7]) {
    HandScore best_score;
    best_score.rank = -1;

    for (int a = 0; a < 3; a++) {
        for (int b = a + 1; b < 4; b++) {
            for (int c = b + 1; c < 5; c++) {
                for (int d = c + 1; d < 6; d++) {
                    for (int e = d + 1; e < 7; e++) {
                        int combo[5] = {cards[a], cards[b], cards[c], cards[d], cards[e]};
                        std::sort(combo, combo + 5,
                            [](int x, int y) { return card_rank(x) > card_rank(y); });
                        HandScore sc = eval_5cards(combo);
                        if (compare_scores(sc, best_score) > 0) {
                            best_score = sc;
                        }
                    }
                }
            }
        }
    }
    return best_score;
}

int eval_hand(const int cards[7]) {
    return find_best_hand(cards).rank;
}

HandScoreFull eval_hand_full(const int cards[7]) {
    HandScore best = find_best_hand(cards);
    HandScoreFull result;
    result.rank = best.rank;
    for (int i = 0; i < 5; i++) {
        result.kickers[i] = best.kickers[i];
    }
    return result;
}

int compare_hands(const int hand_a[7], const int hand_b[7]) {
    HandScore best_a = find_best_hand(hand_a);
    HandScore best_b = find_best_hand(hand_b);
    return compare_scores(best_a, best_b);
}
```

**预期效果**: 消除代码重复，`compare_hands` 不再重复枚举逻辑，代码量减少约40%。

### PERF-04: 静态文件无 ETag/条件缓存

**文件**: [static_handler.py](file:///d:/gitproject/game/texas-poker/server/static_handler.py#L37-L49)  
**严重级别**: 🟡 Medium

**修改方案**: 添加 ETag 支持。

```python
import hashlib

def handle(self, request):
    # ... 现有文件路径验证代码 ...

    file_size = os.path.getsize(file_path)
    mod_time = os.path.getmtime(file_path)

    etag = hashlib.md5(f"{file_path}-{mod_time}-{file_size}".encode()).hexdigest()
    etag = f'"{etag}"'

    if_none_match = request.get_header("if-none-match")
    if if_none_match == etag:
        resp = Response(status_code=304)
        resp.set_header("etag", etag)
        return resp

    # ... 读取文件 ...

    resp = Response(body=data, content_type=content_type)
    resp.set_header("cache-control", "public, max-age=3600")
    resp.set_header("etag", etag)
    resp.set_header("accept-ranges", "bytes")
    return resp
```

```python
    attempts = 0
    while (self.players[start].is_out() or self.players[start].state == "folded") and attempts < n:

        attempts += 1

    self.current_player_index = start
```

### STYLE-03: 缺少 Strict-Transport-Security 头

**修改方案**:

```python
class XSSProtectionMiddleware(Middleware):
    def after(self, request, response):
        response.set_header("x-content-type-options", "nosniff")
        response.set_header("x-xss-protection", "1; mode=block")
        response.set_header("x-frame-options", "DENY")
        response.set_header("strict-transport-security", "max-age=31536000; includeSubDomains")
        response.set_header("referrer-policy", "strict-origin-when-cross-origin")
        response.set_header("content-security-policy", "default-src 'self'; script-src 'self'; style-src 'self'")
        return response
```

**预期效果**: 增强传输安全和内容安全策略。

### ARCH-01: 游戏逻辑与网络层耦合

**文件**: [main.py](file:///d:/gitproject/game/texas-poker/server/main.py)  
**问题描述**: `handle_client` 函数同时处理 WebSocket 协议和游戏逻辑，违反单一职责原则。

**建议**: 将游戏逻辑抽象为 `GameService` 类，WebSocket 处理器仅负责协议转换。

```python
class GameService:
    def __init__(self, connection_manager):
        self.manager = connection_manager

    async def handle_join(self, player_id, room_id, token):
        if not verify_token(player_id, token):
            return {"type": "error", "data": {"message": "authentication failed"}}

        game = self.manager.create_game(room_id, log_callback=log_game_action)
        game.add_player(player_id, f"Player_{player_id}")
        return {"type": "joined", "data": {"room_id": room_id, "player_id": player_id}}

    async def handle_action(self, player_id, room_id, action, amount):
        game = self.manager.get_game(room_id)
        if not game:
            return {"type": "error", "data": {"message": "Not in a room"}}
        result = game.process_action(player_id, action, amount)
        return result
```

### ARCH-03: 缺少结构化日志

**文件**: 所有 Python 文件  
**问题描述**: 使用标准 `logging` 模块，日志格式为纯文本，不便于日志分析系统处理。

**建议**: 使用 JSON 格式日志，包含 request_id、user_id 等上下文信息。

```python
import json
import logging

class JSONFormatter(logging.Formatter):
    def format(self, record):
        log_data = {
            "timestamp": self.formatTime(record),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
        }
        if hasattr(record, "request_id"):
            log_data["request_id"] = record.request_id
        if hasattr(record, "user_id"):
            log_data["user_id"] = record.user_id
        if record.exc_info:
            log_data["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_data, ensure_ascii=False)
```
